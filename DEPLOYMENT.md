# План публикации APEX AUTO

Подготовлено 1 ноября 2026. **Публикация подтверждена. Владелец создал публичный репозиторий; исходники и workflow загружены. Сайт ещё не опубликован: GitHub Pages требуется включить вручную, текущей интеграции API возвращает HTTP 403.**

## Выбранный вариант

- Отдельный **публичный** репозиторий: `urvold/portfolio-apex-auto`.
- Бесплатный GitHub Pages, источник публикации — GitHub Actions.
- Ожидаемый адрес после успешной публикации: `https://urvold.github.io/portfolio-apex-auto/`.
- Публичными станут сайт и исходный код. Домен покупать не нужно. Другие репозитории не затрагиваются.
- Это портфолио-концепт, без реальных заявок, аналитики и платёжных функций.

Аккаунт: `urvold`. Репозиторий создан владельцем вручную после отказа API на создание. Исходники, материалы и workflow отправлены в `main`: https://github.com/urvold/portfolio-apex-auto. Первый запуск Actions: https://github.com/urvold/portfolio-apex-auto/actions/runs/41322793186. Он остановился на чтении Pages configuration, поскольку Pages не включён. POST создания Pages через API вернул HTTP 403 Resource not accessible by integration.

## Что подготовлено

`.github/workflows/pages.yml` запускается при push в `main` и вручную. Сборка на Node 22 выполняет `npm ci`, проверку исходников на типовые секреты, production-сборку и статическую проверку страниц/ресурсов. После успешной сборки отдельное задание публикует только `dist/`.

Actions закреплены на полных SHA официальных действий. Сборка имеет только `contents: read` и `pages: read`; задание публикации — `pages: write` и `id-token: write`. Используется автоматически выдаваемый GitHub токен, вручную добавлять секреты не требуется. Workflow не обращается к другим репозиториям, кроме чтения официальных Actions.

Сборка получает:

- `APEX_BASE_PATH` из `configure-pages.base_path` — `/portfolio-apex-auto/` для этого проекта.
- `APEX_SITE_URL` из `configure-pages.base_url` — полный адрес для canonical, sitemap и Open Graph.

React Router использует basename. Изображения, шрифты, favicon, preload и ссылки учитывают подпапку. Для каждой из 11 страниц генерируется отдельный `/<route>/index.html`. GitHub Pages отдаёт эти страницы и при прямом переходе, и после обновления браузера; адрес без конечного слеша перенаправляется к каталогу. HashRouter и перенаправление всех запросов на главную не используются. Неизвестные адреса получают пользовательский `404.html` со статусом 404.

Добавлены `.nojekyll`, JPEG-обложка для социальных сетей, абсолютные OG URL, canonical и sitemap. Файл `_headers` на GitHub Pages не применяется: это вспомогательный файл для других хостингов.

## Проверки перед подтверждением

```sh
npm run check:secrets
APEX_BASE_PATH=/portfolio-apex-auto/ \
APEX_SITE_URL=https://urvold.github.io/portfolio-apex-auto npm run build
APEX_BASE_PATH=/portfolio-apex-auto/ \
APEX_SITE_URL=https://urvold.github.io/portfolio-apex-auto npm run check:pages
APEX_BASE_PATH=/portfolio-apex-auto/ python tests/pages_smoke.py
```

Smoke-проверка использует обычный статический сервер с подпапкой, каталогами и перенаправлениями, аналогично GitHub Pages. Проверяются все 11 страниц, варианты со слешем и без него, перезагрузка, мобильная навигация, изображения, демо-форма и настоящий 404. Для неё нужны Python, Playwright и Chromium (в текущем окружении доступны).

```sh
APEX_BASE_PATH=/portfolio-apex-auto/ npm run preview -- --port 4180
```

Локальный адрес: `http://localhost:4180/portfolio-apex-auto/`. Это адрес облачного окружения, не публичная ссылка для iPhone. При обычной корневой локальной сборке переменные `APEX_BASE_PATH` и `APEX_SITE_URL` можно не задавать.

Проверка секретов ищет типовые ключи, токены, закрытые ключи, учётные данные в URL и подозрительные имена файлов. Она не выводит найденные значения. Источники также просмотрены вручную; полная гарантия обнаружения любых возможных секретов не заявляется. `.env`, зависимости, сборка, артефакты и Git-метаданные исключены из будущего коммита через `.gitignore`.

## Оставшееся действие владельца

Откройте https://github.com/urvold/portfolio-apex-auto/settings/pages. В разделе **Build and deployment → Source** выберите **GitHub Actions**. Не выбирайте Deploy from a branch, не создавайте новый репозиторий и не добавляйте секреты.

После включения можно повторно запустить подготовленный workflow, дождаться deploy и проверить реальную HTTPS-ссылку и все вложенные страницы. Прежнее подтверждение публикации уже действует; повторное согласие не требуется.

Сайт пока не опубликован; ожидаемый URL не следует считать рабочим до успешного deployment и проверки. Другие репозитории не изменялись.
