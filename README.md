# APEX AUTO

Авторский демонстрационный сайт вымышленного центра автомобильной эстетики. React 19, TypeScript, Vite, React Router; собственная адаптивная CSS-система, Lucide. Backend, аналитика, трекеры и сбор заявок отсутствуют.

## Запуск

Node.js 22+ и npm.

```sh
cd /workspace/portfolio-apex-auto
npm ci
npm run dev
```

Dev: http://localhost:5173. В облачном редакторе откройте порт через его панель Ports/Preview; localhost облачной машины не является localhost вашего компьютера.

Проверка готовой версии:

```sh
npm run build
npm run preview -- --port 4173
```

Откройте URL, напечатанный Vite. Если порт занят, Vite выберет следующий. Preview настроен для правильной выдачи предварительно сгенерированных страниц, в том числе без завершающего слеша.

## Страницы и функции

- `/` — cinematic hero, философия, шесть направлений, проекты, сравнение, процесс, калькулятор, FAQ и CTA.
- `/services` — все направления и расчёт.
- `/services/bodywork`, `/services/painting`, `/services/polishing`, `/services/coatings`, `/services/interior`, `/services/film` — шесть содержательных страниц, этапы, ориентировочные сроки и демо-тарифы.
- `/projects` — фильтры, полноэкранная галерея, предыдущий/следующий кадр, клавиши ←/→ и Escape; сравнение с клавиатурным ползунком.
- `/about` — принципы и процесс концептуальной студии.
- `/contacts` — локальная имитация формы. Данные не отправляются и не сохраняются; после демонстрации поля очищаются.
- Неизвестные маршруты — экран 404; сборка содержит `404.html`.

Калькулятор: базовые демо-тарифы 18 000 / 22 000 / 16 000 / 24 000 / 14 000 / 45 000 ₽, коэффициенты категорий 1 / 1,25 / 1,5; мойка +3 000, диски +4 000, уход за кожей +5 000 ₽. Формула и тариф отображаются в интерфейсе. Реального коммерческого предложения нет.

## Структура

- `src/data.ts` — услуги, тарифы, проекты, FAQ.
- `src/App.tsx` — страницы и повторно используемые компоненты.
- `src/style.css` — токены, сетки, адаптивность, анимации, reduced motion и focus.
- `src/main.tsx` — клиентский вход и гидратация.
- `src/entry-server.tsx`, `scripts/prerender.mjs` — генерация HTML всех страниц с уникальными метаданными.
- `public/images`, `public/fonts` — локальные материалы. Активные изображения WebP, для мобильных — облегчённые версии. Оригиналы сохранены.
- `ASSETS.md` — источники и лицензии.
- `tests/browser_check.py` — функциональная и адаптивная проверка Chromium/Playwright.
- `artifacts/` — локальные скриншоты, JSON и HTML-отчёты Lighthouse (не входят в Git).

## Проверки

```sh
npm run build
APEX_TEST_URL=http://127.0.0.1:4173 python tests/browser_check.py
```

Для браузерного скрипта нужны Python, пакет playwright и Chromium по `/usr/bin/chromium` (в текущем окружении имеются; при переносе адаптируйте путь).

Проверяются 11 страниц × ширины 320, 375, 390, 430, 768, 1024, 1440 px; отсутствие горизонтального переполнения, мобильное меню, фильтры, модальное окно, калькулятор, FAQ, ползунок, отсутствие отправки формы и записи в localStorage/sessionStorage, ошибки JavaScript. Это эмуляция размеров в Chromium, не тестирование на физических устройствах.

Скрипт: `npm exec --yes --package=lighthouse -- lighthouse http://localhost:4173 --chrome-path=/usr/bin/chromium --chrome-flags='--headless --no-sandbox' --output=html --output=json --output-path=artifacts/lighthouse`.

Lighthouse относится к локальной production-главной, а не к опубликованному сайту. Окончательные результаты и ограничения — `VALIDATION.md`.

## Подготовка к публикации

Для GitHub Pages подготовлены basename, ресурсы с учётом подпапки, canonical/sitemap и автоматический workflow. Конкретный план и команды — [DEPLOYMENT.md](DEPLOYMENT.md). Создание репозитория и публикация ожидают отдельного подтверждения.


Готовая статическая версия находится в `dist/`; серверный runtime для размещения не нужен. `.ssr/` используется только во время сборки и не публикуется. Все 11 страниц предварительно сгенерированы. Содержимое и title/description/OG доступны без JS.

1. Выбрать хостинг и домен, подтвердить публикацию отдельно. Внешний репозиторий и размещение не созданы.
2. Отдавать существующие `/<route>/index.html` для чистых URL; неизвестные маршруты должны отдавать `404.html` со статусом 404. Не перенаправлять все запросы на HTML главной. Для nginx подходит `try_files $uri $uri/index.html $uri/ =404;` и `error_page 404 /404.html;`.
3. Задать `APEX_BASE_PATH` и `APEX_SITE_URL` для целевого размещения. Canonical, sitemap и абсолютный OG image генерируются автоматически; GitHub Actions получает эти параметры от Pages.
4. Включить HTTPS и сжатие Brotli/gzip. `_headers` содержит базовые заголовки для совместимых статических хостингов; на остальных настройте их отдельно.
5. Повторить Lighthouse и проверить Safari/iOS и Android на реальных устройствах.

Бизнес остаётся вымышленным. Стоковые изображения не являются кейсами мастерской. Сравнение — явно подписанная цифровая симуляция одного кадра. Для реального запуска потребуются собственные материалы и отдельное проектирование контактов/обработки заявок.
